01 工具更新

Claude Code 官方成绩单：回复前干等从 4 秒多降到 1.3 秒，云端 17 秒→6 秒

"好家伙，Claude Code 每次开始回复前的干等，从 4 秒多砍到了 1.3 秒！😲 官方这份成绩单拿 10 月和 8 月比，只算模型干活之外的等待。本地会话 10 次里有 9 次都能这么快，云端会话省得更多，从 17 秒缩到了 6 秒！"

实用点

官方给出的两个手段可直接借鉴到自建 agent 服务——(1) 用户开始打字时就预热/启动云端会话；(2) 每轮发给模型的整段对话先 gzip 压缩再传。评论区吐槽"之前居然没压缩"，说明请求体压缩这类基础优化在 agent 链路里常被忽略，值得自查。

02 行业趋势

前 Cursor 工程师：AI 老犯同一个错，别先往 AGENTS.md 加规则，按四层优先级修

"AI 老犯同一个错，很多人第一反应是往 AGENTS.md 里加规则，可前 Cursor 工程师说这招要少用！1️⃣ 改代码库 => 架构、类型做扎实…2️⃣ 静态分析 => lint、测试、CI…3️⃣ 文字规则 => 注释、AGENTS.md 强制不了，全靠 AI 自觉，尽量少写 4️⃣ 人工审查 => AI 交代码太快，每个 PR 都仔细审根本审不过来"

实用点

把"约束 agent"从提示词工程转向环境工程：优先让正确写法成为代码库里最容易被抄到的写法，其次用 lint/CI 硬拦截，文字规则只作兜底。对维护 AGENTS.md 越写越长的团队是一个反向信号。

03 工具更新

pstack 插件 /correct：翻提交记录和审查评论，定位 agent 反复犯的错

"pstack 插件里的 /correct，会翻提交记录和审查评论，找出 Agent 老犯的错，从最上面一层开始修。Cursor 和 Claude Code 都能装。"

实用点

是 ITEM2 那套四层方法的工具化落地——用历史 commit 与 review 评论作为"错误样本库"，让 agent 自己归纳高频失误再回到代码库/静态分析层修复。可与现有 AGENTS.md 流程并行试用。

04 其他

开发者让 Claude Code 删掉安卓电视主页广告与预装软件

"他只是把这台电视的商品页发给 Claude Code，问了一句「这个能改吗？」AI 就带他打开开发者模式和无线调试，剩下的全是 AI 自己干的！不过要注意的是，要是删错了开机要用的系统组件，电视会反复重启，只能恢复出厂设置。"

实用点

一个"agent 操作真实设备"的边界案例：AI 能完成开发者模式、无线调试、包管理这一整条链路，但缺少对系统关键组件的风险判断。做设备侧 agent 时，删除类操作需要白名单/回滚保护，而不是靠模型自觉。

05 行业趋势

美国银行额外雇 1000 名外包修 Anthropic Mythos 找到的漏洞

"Bank of America hired 1,000 extra contractors to patch what Anthropic's Mythos found. On top of 3,000 tech staff. Finding bugs got cheap. Fixing them still takes a body at a desk. The bill came lumped in with AML cleanup: 'a couple of hundred million plus.'"

实用点

AI 把"发现"的成本压到接近零之后，瓶颈整体后移到修复与验证环节，且成本以人力形式体现。对安全团队的现实含义：引入 AI 代码审计前先估算修复吞吐，否则漏洞队列只会变长。

06 大佬官方

Anthropic STEM Fellows：Claude Mythos 5 按自然语言指令设计出更优量子电路

"Given plain-language instructions, Claude Mythos 5 designed quantum circuits that improve on the best published ones, sometimes by an order of magnitude or more. More efficient circuits reduce the resources needed by quantum algorithms…"

实用点

值得注意的不是"AI 做科研"这个说法，而是任务形态——有明确可比较基线的结构化设计问题，模型输出可直接与已发表最优解对标。这类"有 ground truth 的设计任务"是目前 agent 落地最稳的一类。

07 关注动态

Grok Bot 实测：自动处理未送达订单的退款，跟完 DHL 与商家

"Bot submitted a refund request to the company, including contacting the DHL. Bot tracked the delivery, followed up with the merchant and just now notified me that the refund appeared back on my credit card. It's automating the worst part the shopping experience: refunds & returns."

实用点

多步、跨主体、长周期的客服类 agent 案例：提交申请→跟踪物流→催商家→确认到账。这类流程的价值在于"跟进"而非"一次调用"，设计上需要持久状态与定时重试；同时该用户此前也提到需向 Bot 提供信用卡信息，权限边界仍是这类 agent 的主要风险点。
