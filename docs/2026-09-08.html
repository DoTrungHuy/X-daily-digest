01 工具更新

Grok Build v1.0.22 大更新：桌面工具接入第一方 MCP 服务器，后台 agent 直接返回输出

"Desktop app tools are now available through a dedicated first-party MCP server, a new long-running workspace daemon can expose folders to Computer Hub, finished subagents can be continued instead of restarted, and background agents now return their actual output directly"

实用点

对 agent 工作流开发者而言，本次更新解决了几个长期痛点：① 内置工具优先于用户 MCP 服务器（避免同名工具冲突）；② 已完成的 subagent 可继续对话而非重启，节省上下文重建成本；③ 后台 agent 完成时直接返回实际输出而非仅给指针；④ 新增 grok-workspaced daemon 模式，可将文件夹暴露给 Computer Hub，适合构建长期运行的自动化任务。安全方面，破坏性 git checkout -- 命令不再自动执行，需经模型确认。

03 行业趋势

AI 编码成本警示：Cursor 月账单超 2 万人民币，Claude Opus 5 成主要开销

"妈蛋的，这个月在 Cursor 上烧了 2 万多人民币！😢 罪魁祸首是 Claude Opus 5，这些顶级模型太贵了，大家在 Vibe Coding 爽飞的同时，也要记得关注成本啊"

实用点

对重度使用 AI 编码工具的开发者，这是一个现实提醒：顶级模型（如 Opus 5）的 token 单价可能让月度账单失控。建议：① 为不同难度任务配置不同模型档位（简单重构用低档，复杂架构才用 Opus 级）；② 关注 CodeBurn 等 token 用量追踪工具；③ 利用 Astra 等新模型的用量优化特性。
