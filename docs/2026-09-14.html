01 大佬官方 / 行业趋势

OpenAI 阐述"两条失败路径"与"pacing ≠ stopping"的完整立场

"There are two ways AI progress could go very badly... First, we could lose control of the future to AI... Second, we could end up in a world with too much concentration of power." / "When we talk about 'pacing', we do not mean 'stopping'... But it should be slower than it otherwise could be; interventions like safety cases and monitoring have significant costs." / "at OpenAI we now formulate explicit safety cases in advance of frontier reinforcement learning runs we expect to significantly increase capability"

实用点

这是把安全实践从"发布前评测"前移到"训练前安全案例"的明确表态。对做 agent/训练基础设施的团队，值得关注的是"安全案例"作为一类可审计工件（类似发布门禁）的形态——如果它成为行业惯例，训练流水线需要预留记录、复现与审批环节。

02 行业趋势

对"250 人响应"的质疑：headcount 不等于控制

"mobilizing 250 people is a response. boards still need the control packet. classify which systems were in the blast radius. name who owns freeze + evidence preserve. stop calling the headcount the stop."

实用点

把事故响应拆成可验收项——影响面清单、冻结责任人、证据保全责任人。对做 on-call/incident response 的工程团队，这是一份不错的自查清单模板（谁 freeze、谁 preserve、谁签字）。

03 行业趋势

强制事件上报 ≠ 调查权：谁有权调取记录、派调查员、保全证据

"OpenAI wants mandatory national incident reporting. fine. boards still ask 'did we file the letter?' The real gap is who can compel records, send investigators, preserve evidence. reporting != investigation."

实用点

区分"合规动作"与"实际控制能力"。做企业 agent 部署时，日志的可导出性、不可篡改性、留存期，往往比"有没有上报流程"更决定事后能否复盘。

04 行业趋势 / 中国相关（无，仅美国立法动态）

Stop Rogue AI Act 与 NIST/FAR 路径：agent 身份不能靠厂商自证

"Congress just told federal deployers: vendor self-attestation is not agent identity. Stop Rogue AI Act (Gottheimer-Lawler) pushes NIST toward continuous agent inventory, crypto-verifiable ID, tamper-evident logs — then FAR puts it on contractors." / "Attestation isnt inventory until someone owns discover / deny / log."

实用点

如果这套语言进入采购条款，agent 侧需要的是三件套：可发现的 agent 清单、可执行的 deny 路径、防篡改日志。现在做 agent 平台的话，把"deny 路径真的会触发"做成可测试项，比写文档有用。

05 行业趋势

Colorado ADMT（SB26-189）2027-01-01 生效：事前告知 + 30 天不利结果解释 + 有意义的人工复核

"Colorado ADMT (SB26-189) hits Jan 1 2027. pre-use notice. 30-day adverse-outcome explain. meaningful human review. if counsel owns the letter but ops owns the model, the board minutes are fiction."

实用点

自动化决策类 agent 若涉及对人产生不利结果，需要预留"解释路径"的单一责任人。工程上意味着决策链路要能输出可读理由，而不是只留一个分数。

06 关注动态 / 工具更新（安全）

levelsio：已关停数月的 VPS 上残留 Claude key 被利用，账单才暴露

"I killed my OpenClaw VPS servers months ago. But today I got a billing alert on its separate Claude account... at some point it got hacked and the Claude key inside OpenClaw got exposed and then they waited for months before using it on Fable 5.1... Anyway I nuked the Claude account, good I kept it on its own separate one"

实用点

三条可立即执行的做法——(1) 下线服务时同步吊销其持有的所有 API key，不要只关机器；(2) 按项目/服务拆分计费账号，隔离爆炸半径；(3) 打开用量告警，因为"被利用"往往先体现在账单而非日志上。密钥泄露后的延迟使用是真实存在的模式。

07 工具更新

Grok Build v1.0.31：多 agent 会话可读性修复，含 MCP 长前缀工具不再被静默丢弃

"Subagent groups now clearly show how many agents are still running versus finished... MCP handling also gets a useful fix....tools with long server prefixes are no longer silently dropped" / "Turn cancelled banners now correctly name the cause instead of always saying 'by user'."

实用点

MCP 工具因 server 前缀过长被静默丢弃，是很容易在生产里踩到的坑——表现为"工具明明注册了但 agent 说没有"。若你在自建 MCP 网关，值得检查自己的工具名截断/规范化逻辑。

Notion 定位延续："从第二大脑变成 agent 的公共大脑"

"notion was my second brain for years.. now it's the common brain for my agents so when i switch from one to another i don't start from zero"
