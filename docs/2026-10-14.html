01 大佬官方

Anthropic 工程博客：为 agent 规模自研版本控制系统，主仓库已从 git 全量迁移

"In May, we merged around 2,500 code changes per day. In September, we merged more than 30,000 per day. As a result, we became bottlenecked by developer infrastructure built for human (rather than agent) scale. ... we share how we built a new version control system—and fully migrated our monorepo from git—in five months"

实用点

这是"agent 吞吐量超过人类基础设施设计假设"的第一个大厂级公开案例。对做 CI/CD、代码托管、monorepo 工具的团队，值得对照自己流水线里哪些环节是按"人提交频率"设计的。注意：新系统（转述称 Scion）目前仅内部使用，无公开版，普通项目仍建议用 git。

02 关注动态

Grok Bot 的"多 bot 邮件互聊"被官方人员当成下一波用法

"it won't be long before 'have your bot talk to my bot' becomes common! some fun use cases of multiplayer grok bot over email could be: debugging (you can send my bot bug reports!), customer support, booking meetings and events, group buys, buying and selling stuff off craigslist"；另有 "ask your bot to email tibo@mail.grokbot.com if you want to send in a bug report!"

实用点

把"agent 间通信"落到最土也最通用的协议——邮件。对做多 agent 协作的人，这是一个低成本互操作样本：不需要共享 runtime，只需要一个双方都能读写的信箱。注意这是官方人员描述的方向，不是已发布的产品能力。

04 行业趋势

莱顿大学研究生 Agent 课教材整本免费上 arXiv：472 页、23 章

"荷兰莱顿大学研究生 Agent 课的教材，整本免费放上了 arXiv！472 页、23 章，从大模型原理一路讲到工具调用、RAG 和多 Agent 协作。只想学做 Agent 助手的话，读第 6~14 章就行。"

实用点

有明确阅读路径（做 agent 读 6–14 章，补原理读 2–5 章），含两个动手作业：写一个会自我反思的 agent 玩 6 个游戏、搭多 agent 医院诊断系统。适合当系统学习的骨架，而不是又一篇散教程。

05 工具更新

Matt Pocock 列出 AI 编程常见 18 个错，并开源精简规则文件的 Skill

"1️⃣ 推理强度开得太高 2️⃣ Skill 写得太长 3️⃣ 盯 Agent 盯得太紧 4️⃣ Agent 干完活，没法自己验证对不对 5️⃣ 全局规则文件塞得太满"；"Matt 每周都会让 Agent 精简一次规则文件，用的是他开源的这个 Skill，一行命令就能安装：npx skills@latest add mattpocock/skills -s writing-for-agents"

实用点

可直接执行的动作是"每周让 agent 精简一次规则文件"，避免 AGENTS.md / 全局规则无限膨胀。注意原帖也提到部分条目互相矛盾（如"开工前没对齐"vs"对齐太勤"），作者回应要按任务大小区分——小改动先改完再对齐。

06 工具更新

Notion 升级 Version History：逐次编辑高亮 diff，并标注是"谁或哪个 agent"改的

"We upgraded our Version History: → See highlighted diffs on every edit → Review row-level database changes → See who (or which agent) made them → Restore an earlier version in a click. Every change across pages and databases is now logged in real time."

实用点

把 agent 的写入和人的写入放进同一套审计与回滚机制，这是"agent 参与协作"绕不开的一环。对做 agent 写权限设计的团队，可参考其粒度：页面级 + 数据库行级 + 操作者身份。

07 中国相关

麦当劳在 GitHub 办 Skill 大赛：用官方 MCP 做 Skill，按 Star 数排名

"比的是用麦当劳官方的 MCP 服务做 Skill，不看评委打分，只看 GitHub Star 数。这个 MCP 接进 Cursor 这类工具后，AI 能帮你查菜单、领券，甚至直接下单。"；"目前只有国内居民能参赛。报名到 10 月 25 日截止"

实用点

一个把 MCP 当真实业务入口（下单、领券）的落地样本，且评审机制是纯 Star 数。排行榜上已有 mcd-git 用 git 命令点餐（add 加购物车、rebase 凑套餐、push 下单）。适合想练 MCP/Skill 但缺真实场景的人。
