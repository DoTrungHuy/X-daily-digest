01 大佬官方

OpenAI 发布 GPT-6.1 Sol：接近 Astra 的智力，价格约五分之一

"GPT-6.1 Sol: near-Astra intelligence for a fifth of the price. It's the most cost-efficient model for its performance available today." / "6.1 Sol at 1/5th of the price of Astra, and 95% cache read discount!"

实用点

若你此前因 Astra 成本而把高价值任务限制在少数场景，6.1 Sol 的价格结构（缓存读取折扣 95%）值得重新做一次成本/质量权衡；官方称其在对齐评测上比 GPT-6 Sol 明显改善，更透明地说明自身局限。注意：这是对上一轮 GPT-6 Sol 的迭代，不是重复发布。

02 工具更新

Ultrafast 速度档上线：Codex 最高 8x、API 最高 6x 生成速度

"Our premium speed tier, Ultrafast offers up to 8x faster token generation (300 tokens per second) in Codex and up to 6x in the API."

实用点

300 tok/s 对 agent 循环（多步工具调用、长链推理）的墙钟时间影响远大于单次对话，值得在延迟敏感的 agent 流水线上实测；目前仅 GPT-6 Astra 可用，GPT-6.1 Sol "coming soon"。同时 OpenAI 重开 Pro 200 并新增 Pro 500（25x Plus），并承诺不再引入 5 小时限额。

@OpenAI 原文1原文2
03 大佬官方

Dots 发布：基于 GPT-6 Astra 的常驻 agent

"Introducing dots, powered by GPT-6 Astra. Remarkably capable, always-on agents built to handle everything." / "We will have a few million dots online within days... We're learning from how you all use your primary dot before releasing the ability to create an entire team of them."

实用点

官方明确"先单个 dot，再开放整队 dot"，说明多 agent 编排仍在观察期；对做 agent 产品的人，这是一个"常驻 + 个人偏好学习"的形态样本，值得关注其权限与持久化设计。

04 大佬官方

sama：ChatGPT Web 在 5 周内基于桌面端代码库重写

"Over the past 5 weeks, the team completely rewrote ChatGPT Web on top of the desktop app codebase. This was only possible with Astra, and it's why Dots, Space, Codex Cloud, and so many more of our launches will come to web and desktop same day. Era of the megaproject begins."

实用点

这是"用模型加速自身工程"的一个具体案例，也是 web/desktop 同日发布的组织性变化；对工程团队的含义是：代码库统一后，跨端发布节奏会被压缩，测试与回滚策略需要提前跟上。

05 工具更新

Codex Security Cloud 升级：默认接入 cyber-capable 模型，持续扫描仓库与提交

"It scans entire GitHub repos, continuously reviews new commits, investigates and deduplicates findings, and prepares fixes for review – even when your laptop is closed."

实用点

把安全扫描从"人触发"变成"持续 + 去重 + 预备修复"，对 CI/安全团队是流程层面的变化；注意"prepares fixes for review"意味着仍需人工把关，不要直接自动合并。

06 行业趋势

Livenerf：锁版本 Claude Code 跑固定 78 题，连测 30 天验证"降智"

"有位开发者搞了个叫 Livenerf 的项目，从 Opus 5.5 发布那周开始，每天用锁死版本的 Claude Code 跑同一套 78 道题，计划连测 30 天，今天冲上了 Hacker News 第一。" / "目前跑了 6 天，最新一天 52.6%，是 6 天里最低的。但前 5 天本来就在 58% 到 64% 之间来回跳，最早 10 月 24 日左右才能下结论，现在喊降智还太早。"

实用点

方法论值得借鉴——锁版本、只挑"时对时错"的题、按标准答案判分、同时监控输出 token（少想会先在这里露馅）。作者也承认目前样本还分不出 Opus 5.5 与 Opus 5 的差异。对依赖模型做长期基准的团队，这是"别用感觉下结论"的正面案例。

07 工具更新

Ollama 支持本地决策模型 Nimble，用于工单分流/模型路由/内容审核

"Ollama now supports Jev-like decision models all locally. Use decision models like Nimble for tasks like ticket triaging, model routing, and content moderation. ollama pull nimble"

实用点

把"路由/分流/审核"这类高频小决策放到本地小模型，是降低 agent 系统成本与延迟的常见做法；官方演示通过新的本地 /v1/systemone API 做实时决策。
